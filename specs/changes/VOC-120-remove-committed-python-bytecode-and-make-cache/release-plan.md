# VOC-120 — Release Plan

## Release and deployment authorization

This package does **not** authorize a new production deploy path, broader
workflow authority, or reduced review rigor.

It removes a generated bytecode artifact from the caller tree, adds portable
Python cache ignore rules to shared infrastructure, and adds fail-closed hygiene
validation. A later develop-to-main promotion of this package follows the
existing A-004 release path and does not itself change application runtime,
deployment topology, credentials, providers, or model routing.

Adoption and task implementation authorization remain separate gates under active
A-004.

## Rollback

| Item | Value |
|------|-------|
| Trigger | Hygiene validation false-positives block legitimate tracked files, or ignore rules become incorrect |
| Mechanism | Revert the T00 ignore-rule and validation changes. Do not re-commit bytecode as the default rollback of the deletion |
| Owner | Implementer PR + independent verification |
| Validation | Re-run governance validation and hygiene tests after revert |
| Last-known-good | Current `main`/`develop` trees before VOC-120 implementation |

## Independent verification, human approvals, and closure

Under **active A-004**, no founder `approved` comment is required on
engineering-workflow gates. Required evidence:

1. Exact-SHA independent verification for the caller implementation PR and for
   any coordinated infra PR.
2. Deterministic proof that `git ls-files` reports no tracked Python
   bytecode/cache artifacts on the caller.
3. Deterministic proof that both repositories' ignore rules cover
   `__pycache__/`, `*.pyc`, and related variants.
4. Confirmation that exact-SHA review, risk floors, protected checks, and retry
   limits remain unchanged.
5. Recorded pin applicability: exact infra merge SHA in `PINNED_SHA.txt` when
   consumed, or an explicit non-consumption note.

Closure: T00 merges with passing deterministic checks and exact-SHA independent
verification, and the recorded evidence shows both repositories meet the hygiene
outcome. Do not conflate package merge with runtime release; this package has no
direct product deployment effect. An issue-close event may wake evaluation, but
closed state alone is not completion proof.
